# Multi-AI Portal

Интерфейс на GitHub Pages, обработка на ноутбуке в Docker. VPS не используется.

## Версия 2.0

- Одна задача, независимые обработчики ChatGPT, DeepSeek и Z.ai.
- История в PostgreSQL, отдельные статусы и ссылки на диалоги.
- Обновление ответов с резервным опросом каждые две секунды.
- Вход в портал с ограниченной по времени сессией; служебный токен остаётся на сервере.
- Claude и Kimi ещё не подключены.

Подключённость процесса не означает выполненный вход в ИИ. Каждый браузерный
аккаунт требует первичной авторизации. Ошибки и CAPTCHA не обходятся;
неоднозначная отправка не повторяется автоматически. Условия и лимиты
подписки определяются сервисами. Проверка реальных ответов после входа обязательна.

## Развёртывание

Запустите `start.ps1`: база, интерфейс и очередь работают в локальном Docker.
Затем `start-chrome.ps1` открывает установленный Google Chrome с отдельным
профилем `.sites-runtime/chrome-profile`. Сначала войдите в DeepSeek и Z.ai
вручную, затем выполните `start-python-bridge.ps1`.

Два независимых Python-процесса используют Playwright и подключаются к Chrome
только на 127.0.0.1:19222. Профили обычного браузера и агрегатора не читаются и
не копируются. Сеанс входа остаётся в отдельном профиле портала. CAPTCHA и
проверки входа требуют пользователя. Флаги маскировки автоматизации не используются.
Вход через Google нужно проверить в обычном Chrome; это не гарантия доступности.

ChatGPT использует отдельный локальный обработчик Codex с существующим входом
по подписке. Он не зависит от этого чата. Для доступа с GitHub запустите
`start-sharing.ps1`. Пароль портала хранится в локальном `.env`; не публикуйте его.
База остаётся в Docker-томе. Ноутбук должен оставаться включённым.
Порт 19222 и профиль Chrome нельзя публиковать через туннель.
Прежние контейнеры браузеров noVNC остановлены; их профили сохранены.

Статический сайт собирается командой:

```
npm install
PORTAL_BACKEND_URL=https://your-backend.example node node_modules/vite/bin/vite.js build --config frontend/vite.config.mjs
```

Результат `dist/pages` публикуется в ветку `main`, каталог `docs`. В GitHub Pages
выберите Deploy from a branch → main → /docs. Для смены адреса туннеля пересоберите интерфейс и обновите каталог `docs`.
GitHub Pages хранит интерфейс. Запросы и история передаются вашему серверу.
Временный демонстрационный HTTPS-туннель меняет адрес при перезапуске:
после этого нужно пересобрать интерфейс. Для постоянной эксплуатации нужен
управляемый домен или постоянный туннель.

## Локальный запуск

Прежний браузерный диспетчер через чат отключён. Веб-модели запускаются
независимыми Python-процессами в Docker.
Локальный адрес: http://localhost:8086.

## Проверки

```
docker compose exec -T api python -m pytest -q
node --test bridge/runner.test.mjs
node node_modules/typescript/bin/tsc --noEmit
```

### Claude: один постоянный чат

В обычном Chrome портала войдите в тот же аккаунт, что в Claude Desktop, и откройте уже существующий чат. Сохраните его HTTPS-адрес в локальном `.sites-runtime/claude-chat.json` в формате `{"url":"https://claude.ai/chat/<UUID>"}`. Файл не публикуется. `start-python-bridge.ps1` запустит отдельный обработчик Claude при наличии этой привязки. Он не создаёт диалоги, не затирает черновики и прекращает отправку при изменении адреса. Выбранная в браузере модель сохраняется самим Claude; текущая настройка — Sonnet 5.5 Low. Все вопросы используют историю этого чата.
